# دليل تسليم اعّرست

آخر تحديث: 27 أكتوبر 2026

هذا الدليل لصاحب المشروع ولأي مبرمج يستلم اعّرست بعد التسليم. هو مختصر
وعملي: ما هو النظام، وأين يعمل، وكيف تشغّله وتحميه، وما الحسابات التي يجب
أن تكون باسمك. التفاصيل التقنية الكاملة في `docs/README.md`.

## ما هو اعّرست

تطبيق عربي لتخطيط الأعراس في اليمن، من ثلاثة أجزاء:

| الجزء | ماذا يفعل | أين الكود |
|---|---|---|
| تطبيق الجوال (Android) | العريس والعروسة والأهل والمزوّدون | `mobile/` (Flutter) |
| الخادم (API) | يحفظ البيانات ويطبّق الصلاحيات ويرسل الإشعارات | `backend/` (NestJS + PostgreSQL) |
| لوحة الإدارة | اعتماد المزوّدين والمراجعات والتقارير | `admin-web/` (React) |
| الموقع العام | الخصوصية، الشروط، الدعم، صفحة التحميل، روابط الدعوات وتأكيد الحضور | `deploy/public-site/` |

اعّرست **لا يستلم أموالًا ولا يحوّلها ولا يقرض**. كل المبالغ تسجيل ومتابعة
فقط، والدفع يتم بين الناس خارج التطبيق. هذا قرار قانوني موثّق في
`docs/project/DECISIONS.md`.

## أين يعمل الآن

- **مؤقتًا على Amazon Web Services** (فرانكفورت): خادم واحد `t3.small`
  يشغّل كل الأجزاء، وتخزين S3 للصور والنسخ الاحتياطية.
- عنوان API الجديد لنسخة اتصال APK هو `https://3.121.198.183`، مع شهادة
  HTTPS عامة للـElastic IP نفسه وتجديد تلقائي من Caddy، دون حاجة إلى دومين.
  راجع [دليل الاتصال المباشر](../../deploy/aws/DIRECT_IP_API.md).
- تبقى العناوين السابقة للمستهلكين الحاليين والإدارة والموقع:
  - API لنسخ APK السابقة: `https://api.3-121-198-183.sslip.io`
  - لوحة الإدارة: `https://admin.3-121-198-183.sslip.io`
  - الموقع العام: `https://3-121-198-183.sslip.io`
- رسائل رمز الدخول (OTP) تُرسل حاليًا عبر واتساب من خدمة OpenWA على خادم
  آخر (rk-server). هذه قناة غير رسمية ومؤقتة؛ البديل الدائم هو واتساب
  الرسمي من Meta (البند 6.1 في قائمة التسليم).

عند التسليم النهائي ينتقل كل ذلك إلى حساباتك ونطاقك (البند 6.9).

قائمة التسليم الوحيدة المعتمدة: `docs/project/V1_DELIVERY_CHECKLIST.md`.
كل بند فيها له حالة: ⬜ لم يبدأ، 🟨 قيد العمل أو ينتظر التحقق على جوال
حقيقي، ✅ منجز ومُتحقق منه، 🚫 خارج النسخة الأولى بقرار.

## قواعد لمن يستلم الكود

1. اقرأ `AGENTS.md` و`ARCHITECTURE.md` قبل أي تعديل. للنظام بوابات فحص
   معمارية صارمة (`npm run architecture` في `backend/`) ولا يُقبل تجاوزها.
2. لا تضع أي سر (كلمة مرور، مفتاح) في الكود أو المستودع؛ الأسرار في ملف
   الإعدادات على الخادم فقط (انظر `ENVIRONMENT.md`).
3. قبل أي نشر فيه تغيير على قاعدة البيانات خذ نسخة احتياطية أولًا.
4. شغّل الفحوصات قبل كل دمج: في `backend/`: `npm run check && npm test &&
   npm run architecture`؛ في `mobile/`: `flutter analyze && flutter test
   --exclude-tags golden`؛ في `admin-web/`: `npm run typecheck && npm test &&
   npm run build`.
