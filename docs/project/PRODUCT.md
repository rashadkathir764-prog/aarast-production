# المنتج

اعّرست نظام يدير الزواج اليمني ماليًا وتشغيليًا، ومعه سوق مزودين. يخدم العريس والعروسة، كل واحد لحاله أو مع بعض، وبمشاركة الأهل بصلاحيات.

**الوعد:** يعرف المستخدم في أي لحظة كم صرف، وكم باقي، وايش ناقص قبل يوم الزواج.

## المتطلبات

| # | المطلوب | التنفيذ |
|---|---|---|
| 1 | عريس وعروسة، لحالهم أو مع بعض أو بالمشاركة | خطة لكل واحد، ومسار العروسة، ومشاركون بصلاحيات |
| 2 | القاعة والفستان والتصوير والذهب والشقة وشهر العسل | بنود المال الجاهزة، والمزودون، والمهام |
| 3 | المصاريف والديون والدفعات (تتبع فقط) | الاتفاقات والدفعات والسلف في «من وين» |
| 4 | المهام الصغيرة قبل الزفاف | المهام والخطوة الجاية وأسبوع العرس |
| 5 | كم صرفت، كم باقي، ايش ناقص | الرئيسية والمال، بأرقام من الخادم |
| 6 | ربط المستخدمين بالمزودين | طلب، عرض، محادثة، حجز، تقييم، وجهة المزود كاملة |
| 7 | الخصوصية | المال مخفي عن المشاركين افتراضيًا، و«أخفِ المبالغ» |
| 8 | يشتغل في اليمن | عربي يمني، وجزء منه بدون نت، وواتساب |
| 9 | مساعد ذكي بحدود | موجود ومطفأ في هذه النسخة |
| 10 | نموذج البيع | الظهور المميز يُفعّل يدويًا من الإدارة |

## الحدود

| مسموح | ممنوع |
|---|---|
| تسجيل ما دفعه المستخدم بنفسه | أي دفع أو تحصيل أو محفظة داخل التطبيق |
| حجز يؤكده المزود بدون دفع | عمولة أو checkout |
| العربون كدفعة عادية في المال | تأكيد استلام مالي من المزود |
| السلفة كمصدر فلوس | تمويل أو إقراض أو أي شيء يحتاج ترخيصًا ماليًا |
| محادثة تبدأ من طلب عرض | رسائل مفتوحة بدون طلب |

## نموذج المال

- `WeddingPlan.estimatedBudget`: الميزانية العامة، بدون المهر.
- `BudgetCategory`: البند.
- `WeddingCost`: اتفاق داخل بند.
- `CostPayment`: دفعة حصلت فعلًا.
- `PaymentSchedule`: موعد دفع، تذكير فقط، لا يحجز ولا يخصم.
- قبول عرض ينشئ `WeddingCost` مربوطًا بالمزود، وبعد تأكيد المزود يصير حجزًا.

## الخصوصية

المال خاص افتراضيًا. لا يظهر لمشارك إلا بـ`canViewMoney`، ولا يعدّله إلا بـ`canManageMoney`. مصادر الفلوس والسلف لصاحب الخطة فقط.
