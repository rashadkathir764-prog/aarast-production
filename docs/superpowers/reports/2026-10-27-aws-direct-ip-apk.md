## التغيير التشغيلي

أضيف عنوان IP إلى Caddy الحالي `v2.10.2`، بنفس الصورة المثبتة
`sha256:4c6e91c6ed0e2fa03efd5b44747b625fec79bc9cd06ac5235a779726618e530d`.
الإعداد يستخدم Let's Encrypt production ACME وملف `shortlived` وHTTP-01.
يختار `default_sni` شهادة الـIP لعملاء TLS الذين لا يرسلون اسم SNI.

تحقّق Python القياسي من TLS دون تعطيله أو تجاوز الشهادة:

- SAN: عنوان IP `3.121.198.183`.
- المصدر: Let's Encrypt، والوسيط `YE2`؛ الاتصال `TLSv1.3`.
- أول صلاحية: `2026-10-27 18:58:28 UTC`؛ نهاية أول شهادة:
  `2026-11-03 10:58:27 UTC`.
- أُعيد تشغيل Caddy، وأعيد استخدام نفس الشهادة من التخزين الدائم وعاد
  `/ready` إلى `200`. لم تمر دورة تجديد كاملة في نافذة المهمة؛ التجديد
  التلقائي مضبوط عبر Caddy، ولا يُدّعى أن تجديدًا فعليًا قد حدث بعد ستة أيام.

إصدار شهادات IP العامة القصيرة متاح رسميًا من
[Let's Encrypt](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability)،
وإعداد ACME موضح في [توثيق Caddy](https://caddyserver.com/docs/caddyfile/directives/tls).
لم يُشتر دومين أو تُنشأ خدمة AWS جديدة أو CloudFront أو خادم بديل.

أعيد إنشاء حاوية Caddy وحدها. بقيت معرّفات وأوقات بدء الحاويات العشر
الأخرى كما كانت، ومنها Backend وPostgreSQL وRedis وAdmin والموقع والنفق
وخدمة تحديث اعتماد OpenWA. أضيف متغير IP العام وحده إلى البيئة؛ قورنت كل
القيم السابقة داخليًا وتطابقت. لا migrations أو تغيير لصلاحيات API أو
تنفيذ كامل لـ`release.ps1` أو تغيير لقاعدة بيانات أو إعدادات أعمال.
